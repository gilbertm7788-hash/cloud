# 텔레그램 봇·채널 설정 가이드

순서대로 따라가면 15분 안에 끝납니다. **3번(봇 관리자 추가)을 4번(chat_id)보다 먼저** 해야 하는 것이 유일한 순서 제약입니다.

## 1. 봇 생성
1. 텔레그램에서 **@BotFather** 검색 (파란 인증 마크 확인 — 사칭 계정이 많습니다)
2. `/start` → `/newbot`
3. **표시 이름** 입력: 한글·공백 가능, 나중에 `/setname`으로 변경 가능 (예: `건설 인사이트 수집봇`)
4. **username** 입력: 5~32자, 영문·숫자·밑줄만, 반드시 `bot`으로 끝나야 함 (예: `construction_curator_bot`)
   - ⚠️ 봇 username은 사실상 변경 불가입니다. 바꾸려면 새 봇을 만들어야 합니다.
5. 출력된 **HTTP API 토큰**을 복사 — `123456789:AA...` 형태(숫자 : 35자 문자열)
   - 이 토큰은 봇의 비밀번호입니다. 저장소 커밋·채팅 공유 금지
   - 유출이 의심되면 BotFather `/mybots` → 봇 선택 → API Token → **Revoke current token**으로 즉시 재발급 (히스토리 정리보다 폐기가 먼저입니다)

## 2. 채널 2개 개설
| 채널 | 공개 설정 | 용도 |
|---|---|---|
| 스테이징 채널 | **비공개** | 봇이 수집 콘텐츠를 자동 게시. 나(운영자)만 구독 |
| 메인 채널 | **공개** (username 지정) | 구독자용. 검토한 콘텐츠만 전달 |

만들기: 채팅 목록에서 연필(새 메시지) 아이콘 → **New Channel** → 이름·설명 입력 → **공개/비공개 선택** → 구독자 초대 화면은 건너뛰기
(데스크톱·웹은 왼쪽 위 햄버거 메뉴 ≡ → New Channel)

**메인 채널 username 정할 때**
- 5~32자, 영문·숫자·밑줄만. 한글·하이픈·마침표 불가. 첫 글자는 문자
- 나중에 바꿀 수는 있지만 **기존 `t.me/...` 링크가 전부 깨지고, 풀려난 이름은 남이 선점**할 수 있습니다. 처음에 신중히 정하세요
- 확정되면 `config/sources.yaml`의 `site.telegram_channel_url`에 `https://t.me/이름` 형식으로 입력 (사이트 하단 채널 버튼에 쓰입니다)

**스테이징 채널에서 반드시 확인할 두 가지**
- **저장 제한(Restrict saving content)을 켜지 마세요.** 켜면 관리자 본인도 전달이 막혀 메인 채널로 옮기는 작업 자체가 불가능해집니다
- **서명(Sign Messages)은 꺼두세요.** 켜져 있으면 전달 시 작성자 이름까지 따라갈 수 있습니다 (기본값 꺼짐)
- 채널 이름에 `[내부]`, 회사명 등을 넣지 마세요. 전달할 때 이름 숨기기를 깜빡하면 그대로 공개됩니다

## 3. 봇을 스테이징 채널 관리자로 추가
봇은 일반 구독자로 추가할 수 없고 **반드시 관리자로 승격**해야 합니다.

1. 스테이징 채널 → 상단 채널명 탭 → 편집(연필) → **관리자(Administrators)** → 관리자 추가
2. 봇 username 검색 → 선택
   - 검색에 안 뜨면 봇과 1:1 대화방을 열어 `/start`를 한 번 누른 뒤 다시 검색
3. 권한은 **"메시지 게시(Post Messages)" 하나만** 켜기
   - ⚠️ **"새 관리자 추가"는 절대 켜지 마세요** (토큰 유출 시 피해가 커집니다)
   - 나머지(채널 정보 변경, 삭제, 초대 링크)도 이 파이프라인에는 불필요합니다
4. ⚠️ **메인 채널에는 봇을 추가하지 않습니다** (실수 게시 방지)

## 4. 스테이징 채널 chat_id 확보
**3번을 먼저 끝냈는지 확인하세요.** 봇이 관리자가 된 이후에 올라온 글만 `getUpdates`에 잡힙니다.

1. 스테이징 채널에 아무 글이나 하나 게시 (봇 승격 후에 올린 글이어야 함)
2. 브라우저에서 열기 (`<TOKEN>`을 실제 토큰으로 교체):
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
3. 응답 JSON에서 `channel_post.chat.id` → `-100`으로 시작하는 13자리 숫자 (예: `-1001234567890`)

**안 나올 때 원인별 대처**
- `Conflict: can't use getUpdates method while webhook is active` (409) → `https://api.telegram.org/bot<TOKEN>/deleteWebhook` 호출 후 재시도.
  ⚠️ `drop_pending_updates=true`는 붙이지 마세요. 찾으려던 글까지 큐에서 지워집니다
- `"result":[]` 빈 배열 → 봇 승격 **전**에 올린 글이거나, 승격 후 새 글이 없는 경우. 글을 하나 더 올리고 재시도
- `401 Unauthorized` → 토큰 오타·공백 혼입·폐기됨
- `404 Not Found` → URL의 `bot` 접두사 누락 (`/bot<TOKEN>/`이 맞습니다)

**대안: 채널 링크에서 읽기.** 스테이징 채널의 아무 글이나 "링크 복사" → `https://t.me/c/1234567890/5` 형태가 나옵니다. `/c/` 뒤 숫자 앞에 `-100`을 붙이면 `-1001234567890`입니다 (마지막 `5`는 메시지 번호이므로 버립니다).
※ 웹 클라이언트 주소창(`web.telegram.org/#-100...`)에서 본 값이 **이미 -100으로 시작하면 다시 붙이지 마세요.**

**등록 전 최종 점검** (`<BOT_ID>`는 토큰의 콜론 앞 숫자)
```
https://api.telegram.org/bot<TOKEN>/getMe
https://api.telegram.org/bot<TOKEN>/getChatMember?chat_id=<CHAT_ID>&user_id=<BOT_ID>
```
두 번째 응답에 `"status":"administrator"`와 `"can_post_messages":true`가 보이면 준비 완료입니다.

## 5. GitHub Secrets 등록
저장소 → Settings → Secrets and variables → Actions → New repository secret:

| 이름 | 값 | 필수 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 (`123456789:AA...`) | 필수 |
| `TELEGRAM_STAGING_CHAT_ID` | `-1001234567890` | 필수 |
| `TELEGRAM_ADMIN_CHAT_ID` | 오류 알림을 받을 별도 채팅 id | 선택 |

- 이름은 **대소문자까지 정확히** 위와 같아야 합니다
- 값에 **앞뒤 공백·줄바꿈이 섞이면 401**로 실패합니다. 붙여넣기 후 끝을 확인하세요
- chat_id는 따옴표 없이 숫자만, `-` 포함
- 토큰 값에 `bot`을 붙이지 마세요. `bot`은 API URL 경로에만 붙습니다

## 6. 첫 게시 테스트
전체를 한 번에 돌리기 전에 소스 하나로 확인하는 것을 권합니다.

Actions 탭 → collect → **Run workflow**
- command: `collect`
- sources: `ikld`
- dry_run: 체크 해제

스테이징 채널에 국토일보 기사가 뜨면 성공입니다. 메시지 모양:
```
📰 [뉴스] 기사 제목
국토일보
요약 문장 (최대 300자)
원문 보기
#건설뉴스 · 전체 공고·아카이브
```
맨 끝 "전체 공고·아카이브" 링크는 GitHub Pages 주소입니다. Pages를 아직 켜지 않았다면 이 링크는 404이므로, 텔레그램과 함께 켜두는 편이 좋습니다 (docs/checklist.md 2번).

## 7. 일일 운영: 스테이징 → 메인 전달
1. 스테이징 채널에서 게시할 메시지를 길게 눌러 선택 (최대 100건까지 복수 선택)
2. **전달(Forward)** → 메인 채널 선택
3. 목적지 채널 화면으로 넘어가면 입력창 위에 "전달된 메시지 N개" 바가 뜹니다. **이 바를 탭 → "보낸 사람 이름 숨기기"** 를 켠 뒤 전송
   - 전달 버튼을 누른 순간 발행되는 게 아니라 여기서 한 번 더 확인 단계가 있습니다
   - 숨기지 않으면 "○○에서 전달됨" 헤더로 비공개 스테이징 채널 이름이 공개 구독자에게 노출됩니다
   - 이 옵션은 기억되지 않으므로 **전달할 때마다 다시 켜야 합니다**
   - 묶음 전체에 일괄 적용되고, 선택 순서와 무관하게 원본 시간순으로 발행됩니다
4. 전달은 서식·링크 미리보기·이미지 원본을 그대로 보존합니다. 문구를 고쳐야 할 때만 복사해서 새로 작성하세요
5. 나중에 원클릭 승인 버튼(copyMessage 기반 자동 전달)으로 업그레이드 가능

## 참고: 속도 제한과 비용
봇 API는 무료입니다. 파이프라인이 전송 간 1.05초 간격을 지키고, 429(속도 제한) 응답을 받으면 서버가 알려준 `retry_after`만큼 기다렸다가 자동 재시도합니다. 한 번에 수십 건이 나가도 실패하지 않고 조금 느려질 뿐입니다.
